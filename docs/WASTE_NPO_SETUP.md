# ติดตั้งระบบติดตามขยะ + รายงาน NPO

หน้า `/waste` คือหน้าเดียวกับที่หน้างานใช้บน Google Apps Script (ฟอร์มบันทึก + Dashboard)
หน้า `/npo` เป็นหน้าใหม่ให้ธุรการออกรายงาน NPO (แทนการกดเมนูในชีต `report_<โครงการ>`)

## ติดตั้ง (ทำครั้งเดียว ต่อจาก docs/CHECKLIST_SETUP.md)

```bash
npm install                    # เพิ่ม sharp (ย่อรูปตอนทำ PDF)
node scripts/migrate_waste.js  # รันซ้ำได้ ไม่ลบข้อมูลเดิม
```

ใช้ตาราง `waste_records` และ `projects` ที่มีอยู่ เพิ่ม:
- `truck_types` อัตรารถ (6 ล้อเล็ก 3 คิว 550 / 6 ล้อใหญ่ 6 คิว 1,100 / 10 ล้อ 13.5 คิว 2,500) แก้ราคาในตารางนี้ได้เลย
- `npo_reports` หัวรายงาน NPO
- `waste_records.npo_id` เที่ยวไหนอยู่ NPO ไหน (แทนตัวนับเดิม), `waste_records.created_at`

## กติกา NPO

- แยกตาม **โครงการ + ประเภทรถ**
- ดึงเที่ยวที่ยังไม่เคยออก NPO เก่าสุดก่อน (วันที่ → เวลาเข้า) จำนวนตามที่ใส่ (ค่าตั้งต้น 50)
- เลข NPO พิมพ์เอง ห้ามซ้ำกับใบที่ยังใช้อยู่ · ช่วงวันที่คำนวณเอง (เดือนไทย ปี พ.ศ.)
- ลำดับเที่ยวนับต่อเนื่องตามโครงการ + ประเภทรถ
- ออก NPO + ทำ PDF อยู่ใน transaction เดียว ถ้า PDF พัง ไม่มีอะไรถูกบันทึก
- ยกเลิก NPO (ต้องใส่เหตุผล) → เที่ยวกลับเป็น "ยังไม่ออก" ออกใหม่ได้ เลขเดิมใช้ซ้ำได้
- เที่ยวที่กรอกย้อนหลังจะไปอยู่ใบถัดไป ไม่หาย

## PDF

A4 แนวนอน หน้าละ 3 เที่ยว รูปเต็มกรอบ 69 × 52 มม. (วัดจาก PDF ตัวอย่างของระบบเดิม)
รูปถูกย่อเป็น 800 × 600 ก่อนใส่ (50 เที่ยว ≈ 7 MB แทน ~30 MB) ความคมตอนพิมพ์เท่าเดิม
ไฟล์อยู่ที่ `public/uploads/npo/<รหัสโครงการ>/`

## ย้ายข้อมูลเก่า

เที่ยวที่เคยออก NPO ไปแล้วในชีต ต้องผูกกับ NPO ด้วย ไม่งั้นจะถูกดึงเข้า NPO ใบใหม่ซ้ำ
(ตกลงวันตัดยอดกับธุรการก่อนย้าย)

## ทดสอบแล้ว (PostgreSQL 16 + Node 22) ผ่าน 32/32

บันทึก + รูป 3 รูป, อัตรารถถูก, กันบันทึกซ้ำ, สัดส่วนไม่ครบ 100 / ไม่มีรูป / ประเภทรถแปลก ถูกปฏิเสธ,
Dashboard ใช้หัวคอลัมน์เดิม, นับค้างแยกตามประเภทรถ, ตัวอย่างไม่บันทึก, ออก NPO + PDF,
เลขซ้ำถูกปฏิเสธ, เที่ยวย้อนหลังไปใบถัดไป, ยกเลิกแล้วเที่ยวกลับมา + ลบไฟล์, ออกใหม่ด้วยเลขเดิมได้,
ไฟล์ PDF หายสร้างใหม่ได้ และถ้า Chrome ที่ใช้ทำ PDF ปิดไป ระบบเปิดใหม่เอง
