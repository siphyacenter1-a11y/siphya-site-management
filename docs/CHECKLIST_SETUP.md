# ติดตั้งเช็คลิสต์ตรวจพื้นที่ฉบับเต็ม (บน server บริษัท)

หน้า `/checklist` ฉบับนี้คือหน้าเดียวกับที่หน้างานใช้อยู่บน Google Apps Script (17 ข้อ, รูป, 3 ภาษา, แดชบอร์ด, ลงนาม GM/GF ด้วยรหัส, แก้ไข, PDF)
ย้ายมาใช้ PostgreSQL แทน Google Sheet

## ขั้นตอนติดตั้ง (ทำครั้งเดียว)

```bash
git pull
npm install                      # ติดตั้ง puppeteer เพิ่ม
npx puppeteer browsers install chrome   # โหลด Chrome สำหรับทำ PDF (~170 MB ครั้งแรก)
                                 # จำเป็นใน npm 11+ ที่ไม่รัน install script ของ puppeteer ให้อัตโนมัติ
node scripts/migrate_checklist.js   # สร้าง/อัปเดตตาราง รันซ้ำได้ ไม่ลบข้อมูลเดิม
```

### บัญชีและสิทธิ์ลงนาม — หน้า `/users` (admin)
หน้า /admin → **👥 จัดการผู้ใช้งาน** → สร้าง/แก้บัญชี และกำหนดสิทธิ์ในหน้าเดียว (`services/users_admin.js`)
- ช่อง: username (สร้างแล้วเปลี่ยนไม่ได้) · ชื่อ-นามสกุล (ขึ้นในใบลงนาม) · รหัสผ่าน ≥ 6 ตัว (แก้ไข: เว้นว่าง = ใช้รหัสเดิม)
- **ประเภทบัญชี**: ผู้ดูแลพื้นที่ควบคุม (`checklist`, กรอกฟอร์ม + ดูแดชบอร์ดเช็คลิสต์ — ค่าเริ่มต้นของบัญชีใหม่) ·
  ธุรการ (`staff`, ใช้ได้ทุกระบบ) · ลงนามอย่างเดียว (`signer`, เฉพาะ GF/GE เห็นแค่แดชบอร์ด) · `admin` เปลี่ยนจากหน้านี้ไม่ได้
  `checklist`/`signer` เปิดหน้าอื่นถูกพากลับ /checklist และเรียก API ระบบอื่นไม่ได้ (`middleware/role_guard.js`, `routes/gas.js`) · มีปุ่ม "ออกจากระบบ" ในหน้าเช็คลิสต์
- **สิทธิ์ลงนามเช็คลิสต์**: เพิ่มได้หลายแถว — GM/ธุรการ (ช่อง 2 + แก้ไข) / GF/GE (ช่อง 3) / MASTER × โครงการ หรือ "ทุกโครงการ"
  ไม่มีสิทธิ์ = กรอก/ดูได้ ลงนามไม่ได้ · เพิ่ม GM/MASTER ให้บัญชีใหม่ → ประเภทเปลี่ยนเป็นธุรการให้เอง · บันทึกแล้วสิทธิ์ทั้งชุดถูกแทนที่ (ตาราง `checklist_pins` ที่มี `user_id`)
  เพิ่ม GF ให้บัญชีใหม่ → ประเภทเปลี่ยนเป็น "ลงนามอย่างเดียว" ให้เอง · บัญชีลงนามอย่างเดียวใส่ GM/MASTER ไม่ได้
- ลบบัญชี → สิทธิ์ลงนามหายตาม (ชื่อในใบที่ลงไปแล้วยังอยู่) · ลบบัญชีตัวเอง / admin คนสุดท้ายไม่ได้
- **รหัส PIN สำรอง (MASTER)** อยู่ด้านล่างของหน้าเดียวกัน — ใช้จากบัญชี admin ที่ไม่มีสิทธิ์ลงนาม
- การเปลี่ยนประเภท/สิทธิ์มีผลทันที ไม่ต้อง login ใหม่
- **ลงนาม/แก้ไขด้วยบัญชีที่ login อยู่** (ไม่ต้องพิมพ์รหัสซ้ำ): ปุ่มลงนาม/แก้ไขขึ้นเฉพาะบัญชีที่มีสิทธิ์ในโครงการนั้น · หน้างานที่ไม่มีสิทธิ์เห็นแค่สถานะ "รอลงนาม/ลงนามแล้ว"
  ผู้ลงนามต้อง login บัญชีตัวเอง (พิมพ์รหัสของคนอื่นแทนจากเครื่องหน้างานไม่ได้) · ชื่อในใบขึ้นตาม `users.full_name` · server ตรวจสิทธิ์ซ้ำทุกครั้ง (`resolveSigner`, `CHECKLIST_myRights`)
- ผู้ลงนามที่ใช้ได้ในแต่ละโครงการ = บทบาทนั้นของโครงการนั้น + บทบาทนั้นแบบ "ทุกโครงการ" + MASTER
- ปุ่ม "แก้ไข" รายการ ใช้บัญชี GM ของโครงการ หรือ MASTER · บันทึกชื่อผู้แก้ที่ `edited_by`
- บัญชี `signer`: login แล้วไป /checklist เห็นเฉพาะแดชบอร์ด — ดู ลงนาม ดู/พิมพ์ PDF ได้ · กรอกฟอร์ม/แก้ไขไม่ได้
  เปิดหน้าอื่นถูกพากลับ /checklist, API อื่นตอบ 403 — กันที่ server: `middleware/role_guard.js` (อ่าน role จากตาราง users ทุก ~15 วินาที)
  และ `routes/gas.js` (`SIGNER_ALLOWED`)
- **MASTER แบบรหัส PIN** (สำรองฉุกเฉิน): ตั้งในหน้า /users ส่วน "รหัส PIN สำรอง" · บัญชี admin ที่ไม่มีสิทธิ์ลงนามจะเห็นช่องใส่ PIN แทน (และบัญชีอื่นที่เป็น admin มีปุ่ม "ใช้รหัส PIN สำรอง")
  (รหัส PIN ของ GM/GF ที่ตั้งด้วยคำสั่งแบบเก่ายังใช้ได้ แต่ควรเปลี่ยนเป็นบัญชี)

### ตั้งรหัส PIN ด้วยคำสั่ง (สำรอง — ปกติใช้หน้า /users)

```bash
node scripts/set_checklist_pin.js add GM 0DJ <รหัส> "ธุรการ 0DJ"   # GM/ธุรการ ของแต่ละโครงการ (เพิ่มได้หลายรหัส)
node scripts/set_checklist_pin.js add GM - <รหัส> "GM สำรอง"        # ใช้ได้ทุกโครงการ
node scripts/set_checklist_pin.js add GF - <รหัส> "GF/GE"           # ช่อง 3 ทุกโครงการ
node scripts/set_checklist_pin.js add MASTER - <รหัส> "Admin"       # ลงนาม/แก้ไขได้ทุกช่อง
node scripts/set_checklist_pin.js list
node scripts/set_checklist_pin.js remove <id>
```

รหัสโครงการอ่านจากวงเล็บท้ายชื่อหน่วยงาน เช่น `ORG Origin Thonglor World (0DJ)` → `0DJ`

แล้ว restart server ด้วย `npm start`

> **อย่าใช้ `npm run dev` กับเครื่องที่ใช้งานจริง** โหมดนั้นรีสตาร์ทตัวเองเมื่อไฟล์ใน `node_modules` ถูกแตะ
> (บน Windows เกิดตอน Chrome ทำ PDF ครั้งแรก) ทำให้การออก PDF/NPO ครั้งแรกล้มกลางคัน

## ใช้งาน

- เปิด `http://<server>:5000/checklist` ต้อง login ก่อน (บัญชี staff ใช้ได้) ถ้ายังไม่ login ระบบพาไปหน้า login แล้วกลับมาหน้าเดิม
- หน้าเว็บเรียก `POST /api/gas` ด้วย `{ fn, args }` แบบเดียวกับ Apps Script (`public/js/gas-shim.js`)

## ตารางใน PostgreSQL

- `site_supervisor_checklists` (เดิม) + คอลัมน์ใหม่ `signer2_at`, `signer3_at`, `edited_at`, `pdf_path`, `pdf_hash`
- `checklist_items` คำตอบรายข้อ 17 แถวต่อฟอร์ม
- `checklist_photos` ลิงก์รูป (ไฟล์อยู่ที่ `public/uploads/checklist/<ปี-เดือน>/`)
- `checklist_pins` รหัสลงนาม (bcrypt)
- `checklist_pin_failures` นับรหัสผิด (ผิด 5 ครั้ง ล็อก 15 นาที)

`checklist_data` (JSONB) ยังถูกเขียนเป็นสำเนา ให้ `/api/checklist/logs` เดิมอ่านได้ต่อ

## ต้องดูแลเพิ่ม

- **สำรองโฟลเดอร์ `public/uploads/`** พร้อมกับ database (รูปและ PDF อยู่ที่นี่ ไม่ได้อยู่ใน git)
- **ฟอนต์ PDF:** ภาษาไทยใช้ `fonts/tahoma.ttf` ที่มีใน repo แล้ว ถ้าฟอร์มกรอกเป็นภาษาเมียนมา/กัมพูชา
  server ต้องมีฟอนต์ภาษานั้น (Windows มี Myanmar Text / Khmer UI อยู่แล้ว, Linux ติดตั้ง `fonts-noto-core`)
- PDF ใช้ Puppeteer ถ้า server ใช้ Chrome ที่ติดตั้งเองแทน ตั้ง `PUPPETEER_EXECUTABLE_PATH` ใน `.env`

## ทดสอบแล้ว (บน PostgreSQL 16 + Node 22)

ผ่านตามรายการตรวจรับในใบสั่งงานทุกข้อ 37/37: บันทึก + รูป, กรอกไม่ครบถูกปฏิเสธ, ช่อง 2-3 ตอนบันทึกต้องว่าง,
รหัส GM ผิดโครงการถูกปฏิเสธ, ลงนามซ้ำไม่ได้, ผิด 5 ครั้งล็อก 15 นาที, แก้ไขแล้วล้างลายเซ็น 2-3,
เปลี่ยนหน่วยงานไม่ได้, รูปเดิมคงอยู่/รูปใหม่เพิ่ม/รูปที่ลบหายทั้งในระบบและไฟล์, ข้อมูลเปลี่ยนระหว่างนั้นต้องรีเฟรช,
ไม่ login เรียก API ไม่ได้, และปุ่ม ดู/พิมพ์ ได้ PDF A4 ภาษาไทยพร้อมรูปจริง

## ลงนามหลายใบ / ประวัติการลงนาม / คลัง PDF
- **ลงนามหลายใบ**: แดชบอร์ด → ติ๊ก "เลือกเพื่อลงนาม" ที่แต่ละใบ หรือ "เลือกทั้งหมดที่รอลงนาม" (ตามตัวกรองที่เลือกอยู่) → "ลงนามที่เลือก"
  ติ๊กยืนยันแล้วกดลงนาม (ใช้บัญชีที่ login อยู่) ระบบเลือกช่องตามสิทธิ์ (GM/ธุรการ → ช่อง 2, GF/GE → ช่อง 3) ใบที่ลงไม่ได้ข้ามพร้อมเหตุผล
  (`CHECKLIST_signMany` — ทั้งชุดอยู่ใน transaction เดียว)
- ทุกการลงนาม (ทีละใบ/หลายใบ) **ต้องติ๊กยืนยัน** "ได้ตรวจสอบแล้ว" · คนเดียวลงสองช่องในใบเดียวกันไม่ได้
- **ประวัติการลงนาม** (`checklist_sign_log`): ใคร ช่องไหน เมื่อไหร่ ทีละใบ/หลายใบ เปิดดูก่อนลงนามหรือไม่ login ด้วยบัญชีไหน
  และบันทึกเมื่อลายเซ็นถูกล้างเพราะแก้ไขรายการ — ไม่ผูก FK เก็บไว้แม้รายการถูกลบ
- **คลัง PDF** (`checklist_pdf_archive`): ลงนามครบ 2 ช่อง → หน้าเว็บสร้าง PDF เก็บเข้าคลังอัตโนมัติ (เบื้องหลัง)
  ไฟล์ชื่อมีเวลา `..._ลงนาม_YYYYMMDDHHMMSS.pdf` ไม่ลบทับ · แก้ไขรายการหลังลงนาม → ฉบับเดิมถูกทำเครื่องหมาย "ถูกแทนที่" แต่ไฟล์ยังอยู่
  ฉบับที่ยังลงนามไม่ครบเก็บแค่ฉบับล่าสุดเหมือนเดิม
- **หน้าคลังเอกสาร `/documents`** (admin เท่านั้น, ลิงก์ "📁 คลังเอกสาร PDF" ในหน้า /admin): รวม PDF เช็คลิสต์ที่ลงนามครบ + NPO + ใบเบิกวัสดุ
  กรองตามระบบ / คำค้น / ช่วงวันที่ / สถานะ และแท็บ "ประวัติการลงนาม" (`services/documents.js`)

## อาคาร / ชั้นที่ตรวจ (1 ใบ = 1 ชั้น)
- หัวฟอร์มมีช่อง **อาคาร** และ **ชั้น** (บังคับ) เลือกจาก dropdown หลังเลือกหน่วยงาน — พิมพ์เองไม่ได้
- รายชื่อมาจากตาราง `transport_floors` ชุดเดียวกับระบบขนส่ง: ตั้งที่ `/transport-entry?project=<รหัส>` → **⚙ ตั้งค่าโครงการ** (admin)
  เป็นข้อมูลในฐานข้อมูล ตั้งบนเว็บได้เลย ไม่ต้องแก้โค้ด · โครงการที่ยังไม่ตั้ง → ฟอร์มแจ้ง "ยังไม่ได้ตั้งรายชื่ออาคาร/ชั้น — แจ้ง admin" และบันทึกไม่ได้
- server ตรวจซ้ำว่าอาคาร/ชั้นอยู่ในรายชื่อของโครงการนั้น (`assertBuildingFloor`) · รายชื่อ: `CHECKLIST_buildings(site)`
- บันทึกแล้วฟอร์มคงอาคารไว้ ล้างแค่ชั้น (ใบถัดไปมักเป็นชั้นอื่น)
- แสดงใน: หัว PDF, การ์ดแดชบอร์ด, หน้าต่างลงนาม/แก้ไข, CSV, คลังเอกสาร (ค้นด้วย "อาคารA ชั้น 3" ได้), ชื่อไฟล์ PDF
- แดชบอร์ด: เลือกโครงการแล้วมีตัวกรอง **อาคาร/ชั้น** เพิ่ม · ใบเก่าก่อนมีฟีเจอร์นี้แสดง "ไม่ระบุอาคาร/ชั้น" (แก้ไขใบนั้นต้องเลือกอาคาร/ชั้นก่อนบันทึก)
- คอลัมน์ `site_supervisor_checklists.building / floor` และ `checklist_pdf_archive.building / floor` (migration รันซ้ำได้)
